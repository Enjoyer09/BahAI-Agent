## Railway UI correction (user: no "Clear build cache" button in Settings → Build)
- User confirmed there is NO "Clear build cache" button in the current Railway dashboard. Verified via Railway docs:
  the current method is an env var, NOT a button. Official: set `NO_CACHE=1` in service Variables, then Redeploy;
  remove the var after a successful build to keep future builds fast. (Old guides also mention `railway project reset-cache` CLI
  or a Settings → Advanced/Danger Zone button, but the reliable cross-version method is `NO_CACHE=1`.)
- Also CRITICAL: the user must Redeploy the LATEST commit (f04c7998/7e4011d5), not an old deployment — Redeploying an old
  deployment re-runs that old commit (which is why changes never appeared). With NO_CACHE=1 + latest commit, the build copies
  fresh backend/ (with perf fixes).
- Fallback if still stale: push a small real change to a backend file (new commit on main) → Railway auto-deploys latest + NO_CACHE.
