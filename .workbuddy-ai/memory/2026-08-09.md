### Bug found: tool-call JSON leaks into the user-visible chat
- Symptom: when the model attempts a web_search tool call to fact-check, the raw
  JSON (`{"name":"web_search","arguments":{...}}`) appears as a code block in the
  user-visible assistant message instead of being hidden / executed.
- Root cause candidate: `frontend/src/lib/chatRuntime.ts normalizeAssistantText` is
  supposed to strip tool-call JSON (tests confirm `{"name":"web_search"...}` → ''),
  but it doesn't match TRUNCATED / malformed JSON like `{"` (the regex likely needs
  the full pattern). So a half-emitted tool call falls through to the user.
- Fix direction (not done): broaden normalizeAssistantText to also strip any code
  block whose content begins with `{` and resembles a tool-call fragment, AND/OR
  ensure the runner never streams a partial tool-call frame as visible text.
- This is the SAME class of bug as chatRuntime.test.ts line 54-81 already guards
  against for whole JSON — but truncated fragments slip through.

## (b) fix COMPLETED — backend runner/stream never emits partial tool-call frame
User chose option (b): "runner heç vaxt yarımçıq tool-call frame-ini görünən mətn
kimi axın etməsin; ya tam tool call tamamlanmayınca göndərməsin, ya da görünməz
kanalda saxlayıb yalnız nəticəsini userə göstərsin."

Root cause (confirmed by reading the pipeline):
- Model emits the tool call as TEXT (not via delta.tool_calls). `collectStreamOutput`
  (backend/chat/stream.js) streamed each `delta.content` chunk live as
  `assistant_delta`. At stream END, `extractTextToolCalls` removes ONLY COMPLETE
  tool-call JSON. If the stream was cut off mid-frame, the truncated `{"` /
  unterminated ```json survives into `message.content` → frontend renders it as a
  code block. That is the `"{` symptom in the screenshot.

Changes (backend/chat/stream.js only):
1. Added `findToolCallFrameStart(text)` — detects the OPENING shape of a tool-call
   frame (```json{ , bare {"name":...} , or ["tool", ...]). Matches opening shape
   only, so truncated frames are still caught.
2. Added `stripPartialToolCallFragments(text)` — FINAL SAFETY NET that removes any
   leftover partial/truncated tool-call JSON (unterminated fence, unbalanced
   {"name"...} object, dangling `{`) from the final `accumulatedContent`.
3. Replaced the brittle `deferStructuredOutput` boolean with an `emittedLen` +
   `holdFrom` streaming guard: live-emit only the safe prose BEFORE a tool-call
   frame; withhold from the frame start; flush trailing prose at end (after the
   frame is extracted/stripped). A complete text tool call is extracted and only
   its RESULT is shown; a truncated frame is never shown at all.
