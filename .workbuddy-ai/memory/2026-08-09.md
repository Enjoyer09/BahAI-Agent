## Weather "hardcoded template" concern — investigated, NOT a bug
User suspected the agent always returns the same canned Baku weather from a code
template ("həmişə eyni cavab"). Verified it is NOT hardcoded:

- `backend/routes/chat.js` (≈L232-251) fetches **live** from
  `https://wttr.in/{City}?format=%C|%t|%w|%h` for current conditions and
  `?format=j1` for "sabah/tomorrow" forecast. The sentence is a template, but the
  numbers are real-time API data.
- Live proof: `curl wttr.in/Baku?format=%C|%t|%w|%h` →
  `Light rain shower|+22°C|↑7km/h|85%`, which matches the agent's reported
  "light rain shower, 22°C, 85%". So the agent tells the truth, live.
- Why it "looks the same every time": weather doesn't change minute-to-minute,
  and this is a direct-reply short-circuit that bypasses the LLM (fast path for
  simple weather questions) — by design, not a defect.
- The "35°C very hot today" mismatch the user heard is a real FEATURE GAP, not a
  hardcoded bug: the handler only reports CURRENT conditions ("hazırda"=now).
  It does NOT compute today's forecast HIGH — only "sabah/tomorrow" (j1
  weather[1].maxtempC) is implemented. So it can't confirm/deny a 35°C day-high.
  Offer (not yet done): extend the weather path to also surface today's max
  (j1 weather[0].maxtempC) when the user asks "bugün/today".
