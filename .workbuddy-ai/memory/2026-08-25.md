## Buddy Ekran Kompanyonu (Feature #2 of 4) — SHIPPED

After #1 was pushed and the queue was confirmed, bahaI said `#2 ye kec`.
Goal: user can share their screen with Buddy from the desktop app, and the
web_chat agent can ground its next turn on what they actually see.

### Architecture decision
Captures stay **per-user** in memory + on disk (no broadcast), and the
`capture_my_screen` tool just reports status. When `appendToConversation=true`
on upload, the PNG is INSERTed into `messages` with `attachments=[{type:image}]`
so the existing chat pipeline renders it and feeds it to the vision model on
the next turn. **No new streaming/SSE path** — reuses existing chat pipeline.

### Backend files (new + modified)

  - `storeScreen(userId, {base64, mimeType, dataUrl, conversationId})` — TTL 2min,

  - `getStatus(userId)` — `{hasScreen, ageMs, ttlMs, expiresInMs, mimeType, bytes, conversationId}`.
  - `appendScreenShareToConversation({userId, conversationId})` — INSERT into

### Incidental server-boot bug fix
While running tests, discovered `ensureAppsDir()` was async (returns Promise)
but used in `const APPS_DIR = ensureAppsDir()` without await → server failed
to boot in `app.use('/apps', express.static(APPS_DIR, ...))`. Fixed by making
it sync (`fs.mkdirSync` recursive). This bug was introduced in #1 commit
(b8ef46ab) but only surfaced under integration-test conditions.
